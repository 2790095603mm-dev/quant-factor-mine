### 这次运行里值得注意的几件事

1. **规划不是硬编码的。** 计划里的「银行」「最近一年」「bp, ep_ttm」都是从请求文本
   解析出来的槽位；把请求换成「对比最近两年白酒股的 roe 与 gross_margin 因子」，
   计划会变成 3 个因子的实验 + 一个因子对比步骤 + 行业中性与 Decay 设置。
2. **第 10 步改变了后续走向。** 异常检查报出高优异常（截面 42 只 < 100 只），
   运行时据此补了一段计划，自动跑宽基对照。这是整个流程里唯一「自主决定下一步」的
   地方，且范围被限制为「只换股票池」。
3. **报告以主实验为正文、对照单独成节**（见下方报告节选），因为用户问的是银行股。
4. **合成数据被显著标注**，不在文末小字里提一句（见下方横幅）。

## 二、研究报告节选（落盘产物）

路径：`reports/agent_runs/<run_id>/artifacts/research_report.md`

```markdown

> ⚠️ **本报告基于合成面板，不是真实行情数据。**
> 面板由 `qfm.agent.synthetic` 确定性生成，并人为植入了弱价值效应，仅用于演示
> Agent 的研究流程（规划 → 取数 → 计算 → 检验 → 异常检查 → 报告）。
> 其中的 IC、收益、回撤等数字**不构成任何实证结论**，不能用于推断真实 A 股市场
> 上任何因子的表现。

## 一、研究配置

- 股票池：industry:银行Ⅱ（42 只标的）
- 区间：2025-09-18 ~ 2026-09-18（262 个交易日）
- 组合：long_only，持仓 30 只，调仓 ME，中性化 none

| 预测力 | IC 为正占比 | 57.02% |
| 组合 | 年化收益 | +6.41% |

## 三、分层与单调性

**不可用。** 分层检验要求每日至少 100 只有效股票，本次股票池为 42 只，未达门槛。
因此本报告只能依据 IC 判断因子的预测力，无法验证分组区分度。

## 五、宽基对照（index800，170 只）

主实验的股票池截面偏窄，无法进行分层检验。为判断结论是否受样本宽度影响，
在同一区间、同一组合配置下改用 index800 重跑了一次。两次实验**只有股票池不同**。

| 指标 | 主实验（窄池） | 宽基对照 | 差异 |
| --- | --- | --- | --- |
| 股票池标的数 | 42 | 170 | — |
| IC 均值 | +0.0346 | +0.0252 | -0.0094 |
| IC t 值 | +3.93 | +4.30 | +0.37 |
| IC 为正占比 | 57.02% | 65.29% | 8.26% |
| 年化收益 | +6.41% | +10.54% | +4.12% |
| 年化超额 | +2.25% | +2.01% | -0.24% |
| 夏普比率 | 1.6069 | 2.0266 | 0.4197 |
| 最大回撤 | -2.37% | -5.70% | -3.33% |
| 分层检验可用 | 否 | 是 | — |

**对照结论：** 两次实验的 IC 方向一致，说明该因子在窄池上的表现不是样本宽度造成的
假象；但数值差异反映了行业构成的影响。

## 异常检查（主实验）

### 🔴 narrow_cross_section（high）

股票池仅 42 只，截面宽度不足；IC 的统计功效受限，结论对单只股票的异常表现更敏感

- 证据：`n_symbols=42`, `threshold=100`
- 建议：改用更宽的股票池（如全市场或沪深300）重跑，以获得分层统计与更稳健的 IC

## 结论与局限

- **预测力：观察到显著的正向预测力。** IC 均值 +0.0346（t=+3.93），
  IC 为正的交易日占 57.0%，方向与因子定义一致。
- **组合表现：** 年化超额 +2.25%，组合跑赢等权基准。
- **稳健性（宽基对照）：** 在 index800（170 只）上 IC 均值为 +0.0252，方向与主实验一致。
- **局限：**
  - 主实验股票池仅 42 只，截面偏窄；分层检验因样本不足无法进行。
  - 缺少分层单调性证据，无法排除「排序能力只集中在极端层」的可能。
  - 本结论仅覆盖所测区间，未做样本外验证，也未考虑涨跌停与流动性约束的真实冲击。
```

## 五、重试与「静默降级」

重试不是「捕获异常后 sleep 重试」那么廉价。真实数据上实测触发过一次：

```text
   5. ▶ compute_factor     计算 bp 因子值并核对覆盖率
      🔁 第 1 次失败（transient）：因子 bp 覆盖率仅 15.1%，低于下限 30%…
      🔁 第 2 次失败（transient）：因子 bp 覆盖率仅 15.1%，低于下限 30%…
      ❌ FAILED　[尝试 3 次]
```

这次失败暴露的是**工具本身的缺陷**（面板被加载成 1991–2026 全历史 8604 天，
而财务数据只有 2020 年起，覆盖率被历史区间稀释），修复方式是让 `load_panel`
裁剪到分析窗口。这个缺陷的存在与修复过程本身就是重试机制的价值证明：
**没有重试与结果校验，这个「覆盖率 15% 却看起来成功」的因子会被算进结论。**

机制细节：

- 异常分类决定是否重试（瞬时故障重试、参数错误立即失败）；
- 结果校验覆盖「无异常的失败」——`DegradedResultError` 是
  `TransientError` 的子类，静默降级因此也会被重试；
- 每次失败都在轨迹里留下错误类型、分类、退避时长。

对应的测试：`tests/test_agent_retry.py`（26 个用例）、
`tests/test_agent_runtime.py::test_transient_tool_failure_is_retried_then_succeeds`。

## 六、上下文管理在真实数据规模下的表现

把报告里的上下文统计拉出来看：

```text
上下文：22 条 / 2716 字符（外置 2 条，折叠 0 条）
```

整轮运行（含对 799 只股票的面板操作、三张因子矩阵、三次实验）在对话上下文里
只占 **2716 字符**。原因是三层策略：

1. 工具返回 `(payload, summary)`，上下文只收 `summary`，完整对象留在 `ToolContext`；
2. 超限内容写进 `artifacts/`，上下文只留摘要 + 路径；
3. 总长超预算时从最旧开始折叠成占位说明（`pinned` 的请求与计划豁免）。

对照数字：`run_experiment` 的内部结果是 IC 序列 + 分层收益 + 净值曲线 + 交易明细，
`compute_factor` 的返回是 582×170 的浮点矩阵。这两个对象若序列化进上下文，
量级在 MB 级。

算法与边界用例：`tests/test_agent_context.py`（22 个用例，含「折叠最旧而非最新」、
「置顶豁免」、「折叠保留占位而非删除」）。

`tests/test_agent_demo_numbers.py` 锁定的：该测试用合成面板跑同一句请求，
断言主实验与对照实验的关键指标（IC、t、ICIR、年化、夏普、回撤、换手、
标的数、异常代码集合）与本文一致。数字变了测试就会失败，从而强制同步文档——
手抄数字迟早会和代码漂移。

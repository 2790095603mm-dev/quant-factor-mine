# 研究项目工作台设计

## 目标

在不重写现有因子、ML 合成和回测内核的前提下，为 A 股日频研究提供可保存、可复现、可比较的本地研究账本。研究员应能创建项目，将一次完成的组合回测保存为运行记录，在重启后仍能查看配置、数据快照、净值、权重、成交与关键绩效，并在项目内横向比较多次运行。

本期不接入实盘、云同步、多人协作、任务队列或数据库服务。

## 备选方案与决策

1. 仅用 Streamlit `session_state` 保存最近一次回测。实现最少，但刷新页面和重启服务后记录消失，无法满足研究可复现性。
2. 直接部署 SQLite/MLflow。查询和多人能力更强，但为单机项目引入迁移、服务运维和依赖成本，超出本期目标。
3. 本地文件研究账本。以 JSON manifest 和 CSV 产物保存项目与运行；可直接检查、备份和导出，且无需新服务。

采用方案 3。数据格式保持公开、扁平、可迁移，之后可将相同领域模型接到 SQLite 或 MLflow。

## 领域模型与存储

根目录为 `data_cache/research/`：

```
research/
  projects/<project_id>.json
  runs/<run_id>/
    manifest.json
    nav.csv
    benchmark_nav.csv
    weights.csv
    yearly_performance.csv
    trades.csv
```

`ResearchProject`：`id`、名称、描述、创建时间、更新时间。

`ResearchRun` 的 `manifest.json`：

- 标识：运行 ID、项目 ID、名称、创建时间；
- 研究配置：因子列表、合成方法、前瞻期、估权窗口、正交化设置、持仓数、调仓频率、基准、起止日期和成本假设；
- 数据快照：股票池、股票数、数据起止日期、交易日数量；
- 结果摘要：净值终值、策略与基准绩效、换手、成本、成交笔数；
- 产物文件名和格式版本。

项目名称不能为空、最长 80 个字符；运行名称为空时由系统生成。保存过程先写入同级临时目录，全部成功后再原子替换为最终运行目录，避免半写入记录被项目页读取。加载损坏或旧版本记录时应跳过该条并向页面返回可理解的错误说明，不阻断其他项目和运行。

## 页面与数据流

侧边栏新增“研究项目”入口，并始终展示当前活跃项目名称。

研究项目页提供：

1. 创建项目、选择当前活跃项目；
2. 当前项目的运行表，含运行名称、时间、因子、年化收益、夏普、最大回撤、换手、成本和数据区间；
3. 多选运行的净值对比图；
4. 单次运行详情：完整配置、权重、分年绩效、成交记录和 CSV 下载。

策略回测页保持现有配置和运行逻辑。一次回测成功后，结果留在 `session_state`；用户填写运行名称并点击“保存至当前研究项目”后才持久化。若没有活跃项目，页面说明如何创建；不会暗中创建项目或自动写盘。保存成功后显示运行 ID，并提供跳转到研究项目页的入口。

```text
用户设置回测参数
  → synthesize / run_backtest（现有内核）
  → 展示本次结果（现有页面）
  → 用户明确保存
  → ResearchStore.write_run
  → manifest + CSV 产物
  → 研究项目页加载、筛选、比较、下载
```

## 边界与可复现性

- 本期只保存已完成的策略回测，不保存挖掘或单因子检验运行；领域层设计允许后续加入其它运行类型。
- 不复制原始行情数据；manifest 记录数据范围和股票池，原始数据版本管理仍由既有 `DataLoader` 缓存负责。
- 保存的净值、权重、分年绩效和成交来自当次内存结果，不会重新运行策略，因此回放不会被后续代码或缓存变化静默改写。
- 使用“研究记录”而非“已验证策略”措辞；项目页展示的是历史模拟结果，不能作为实盘建议。

## 文件边界

- 新增 `qfm/research/models.py`：不可变的项目、运行、快照与载荷数据结构，以及序列化验证。
- 新增 `qfm/research/store.py`：本地存储、原子写入、读取、列表和加载产物。
- 新增 `qfm/research/__init__.py`：公开研究账本接口。
- 新增 `tests/test_research_store.py`：临时目录下的项目、运行、往返、排序与损坏记录测试。
- 修改 `app.py`：导航、活跃项目 session state、保存控件、研究项目页和运行比较展示；不改变既有回测计算公式。
- 新增本期实现计划到 `docs/superpowers/plans/`。

## 验收与测试

1. 可创建、列出并切换项目；空名称被拒绝。
2. 使用合成的 `BacktestResult` 保存一次运行后，配置、指标、净值、权重、年度绩效和成交记录都可无损读回。
3. 多个运行按创建时间倒序列出，损坏 manifest 不破坏其余记录加载。
4. 保存写入失败不会留下最终可见的半成品运行目录。
5. 现有全量 pytest 仍通过；新增测试无需网络或真实 A 股缓存。
6. 本地 Streamlit 页面能创建项目、执行或加载一次回测结果、保存运行并在研究项目页看到该运行。

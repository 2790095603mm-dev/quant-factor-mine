# 数据快照审计设计

## 目标

让保存到研究项目的每次回测都能回答三个问题：当时实际用了哪些证券、这些数据的可用性如何、之后重新运行时底层数据是否已变化。本期只补充研究记录的可追溯性，不改变因子、选股、交易成本或回测收益计算，也不复制原始行情文件。

## 方案比较与决策

1. **仅保存起止日期、股票数和股票池名称。** 几乎没有成本，但无法区分同名股票池的成分变化，也不能发现缓存行情或财务数据被刷新。
2. **复制本次使用的全部行情和财务数据。** 回放最完整，但每个运行会重复保存大量 parquet，单机研究账本迅速膨胀，且超出本期需求。
3. **保存参与回测的证券列表、覆盖率、来源口径和确定性内容指纹。** 可识别实际样本、缺失数据和底层内容变化，存储量很小；需要复算时仍使用本地缓存或原数据服务。

采用方案 3。它是本地研究平台在正式引入数据版本库前最实用的中间层。

## 快照结构

保留现有顶层字段 `pool`、`stocks`、`trading_days`、`data_start`、`data_end`，使旧运行和既有页面兼容；新增以下可选字段：

```json
{
  "snapshot_version": 2,
  "stock_codes": ["000001", "600000"],
  "universe_fingerprint": "sha256:...",
  "sources": {
    "market": "akshare:sina-qfq",
    "fundamentals": "akshare:eastmoney-yjbb"
  },
  "coverage": {
    "close": 0.98,
    "open": 0.98,
    "amount": 0.98,
    "industry": 0.84,
    "fundamentals": {"roe": 0.72, "eps_ttm": 0.69}
  },
  "fingerprints": {
    "market": "sha256:...",
    "fundamentals": "sha256:..."
  },
  "quality_warnings": []
}
```

证券代码按字符串、六位零填充后排序。`universe_fingerprint` 对日期和代码序列哈希；`market` 指纹覆盖本次面板使用的 OHLCV、成交额、换手率和流通市值；`fundamentals` 指纹覆盖已公告对齐后的财务字段和行业归属。哈希按字段名、索引、列名和值的固定顺序增量生成，因此相同面板必得相同结果，任一已纳入字段变化会改变对应指纹。

覆盖率为非空单元格占比。`quality_warnings` 只报告客观可观察的缺口：空面板、价格字段覆盖率低于 95%、成交额覆盖率低于 95%，以及没有可用财务或行业字段；它不对策略质量下结论，也不把自然存在的早期财务缺失误报为数据错误。

## 组件与数据流

新增纯函数模块 `qfm.research.snapshot`：

- `build_data_snapshot(panel, pool)`：验证非空日频面板，计算代码、区间、覆盖率、警告和两个内容指纹，返回仅含 JSON 标准类型的数据；没有 Streamlit、文件写入或网络调用。
- `qfm.research.payload.build_strategy_run_payload`：调用该函数，替换手写的简略数据快照；仍只在回测成功后构建内存载荷。
- `qfm.research.views`：对新快照渲染一张紧凑“数据快照审核”卡，显示样本区间、代码数、关键覆盖率、短指纹和警告；旧运行缺少新字段时退化为原始 JSON，不报错。

```text
已完成回测 + DataPanel
  → build_data_snapshot（纯计算）
  → latest_strategy_run（会话内）
  → 用户点击保存
  → ResearchStore manifest.json
  → 研究项目页审核、比较与下载
```

哈希仅在用户点击“运行策略回测”且回测成功后的载荷构建中计算一次，保存时不重新计算策略。它不以哈希替代原始数据备份；加载运行只展示当时记录的审计信息，不能静默假定现在的缓存仍相同。

## 失败处理与兼容性

- 空日期或空证券面板在构建快照时抛出清晰 `ValueError`；已有回测在此前本就无法产生有意义结果。
- 缺少可选字段（`amount`、`industry`、`fund`）记录为零覆盖或相应警告，不中断保存。
- 哈希函数明确包含字段边界，避免字段拼接产生歧义；将 DataFrame 值以稳定的 pandas 哈希增量更新，不序列化为巨型 JSON 字符串。
- 研究记录格式版本保持为 1：新快照字段是 `data_snapshot` 中向后兼容的扩展。旧 manifest 可继续被读取，并在界面显示“该运行未记录扩展审计信息”。

## 测试与验收

1. 同一合成 `DataPanel` 生成完全相同的快照、证券列表与两个指纹。
2. 改变一个行情单元格只改变市场指纹；改变一个财务单元格只改变财务指纹。
3. 缺失行情和可选字段会得到可预测的覆盖率和警告，且不访问网络。
4. 策略运行载荷包含扩展快照且保持 JSON 安全。
5. 旧的简略快照仍能在研究项目页查看，不会导致运行加载失败。
6. 全量 pytest、研究工作台冒烟脚本和本地 Streamlit 健康检查通过。

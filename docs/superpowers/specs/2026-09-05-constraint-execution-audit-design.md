# 约束执行差异审计设计

## 目标

将组合约束的“计划目标”与执行日收盘的“实际仓位”放在同一条调仓审计记录中。研究员需要能分辨：约束是否成功限制目标、计划成交额预算是否绑定，以及因成交容量、涨跌停、停牌、交易成本或开盘到收盘价格变化造成的实际暴露偏离。

## 方案与决策

1. 使用每日 `holdings` 在页面事后重算。它依赖 `store_holdings=True`，不能服务于轻量挖掘回测，也缺少与具体目标的直接关联。
2. 在每次执行日收盘后追加实际仓位审计。现有 `constraint_history` 已按调仓存储目标与预算，将实际指标写回同一行，数据量小且目标/实际天然对应。
3. 保存每笔成交或拒单的详细原因。最精确，但需扩展订单状态机和存储格式；当前成交表也没有未成交订单实体。

采用方案 2。它不判定“策略违规”，只描述收盘实际暴露相对计划目标的差异；实际超出目标上限可能是无法卖出、价差或当日价格变动，而不是目标构建器失效。

## 审计字段

每条 `constraint_history` 在保留目标字段后追加：

- `actual_invested`、`actual_cash`、`actual_positions`：收盘实际股票权重与现金；
- `actual_max_stock_weight`、`actual_max_industry_weight`：按收盘市值计算的最大单股/行业权重，缺失行业归为 `未知行业`；
- `target_tracking_error`：实际股票权重与预算后执行目标的绝对偏差之和；未持有、未被目标选中和目标未成交的证券均包含在内；
- `stock_cap_exceeded`、`industry_cap_exceeded`：实际最大暴露严格大于目标上限加 (10^{-8}) 的布尔提示。

实际行业暴露从执行日 `panel.industry` 和收盘价值计算。行业缺失在审计中归类为 `未知行业`，与目标构建一致。即使不存储全量每日持仓，执行日已有的 `shares`、`cash`、收盘价和目标足以计算这些字段。

## 数据流与界面

执行日开盘先完成原有卖出、买入和成本处理；收盘盯市计算实际价值后，回测将此前暂存的目标诊断、预算诊断和实际指标合并为一行。没有目标或没有执行的日期不会产生审计行。

策略页的“组合约束执行”摘要改为同时展示目标现金与实际现金、跟踪偏离和实际超限状态。明细表保留所有字段，并在说明中强调它是收盘快照，不是订单拒绝原因。研究运行继续通过已有 `backtest.params` 归档约束配置；本期不增加新的 CSV 产物。

## 验收

1. 普通可交易回测产生非空实际字段，且实际现金/持仓数范围合理。
2. 制造开盘无法买入情形时，实际现金高于目标现金、跟踪偏离为正；目标约束字段不被改写。
3. 实际行业/单股暴露以收盘价值计算，未知行业不会漏计。
4. 无约束的旧调用仍可运行，已有全量测试和研究账本冒烟通过。
5. 策略页面能在隔离实例显示目标/实际并排指标和说明。
